# The GPU add-on in Settings and the wizard: plan

> 11 Oct 2026. Status: a proposal for the founder; nothing in it is built. It is the second half of WP5 of `docs/plans/2026-10-10-gpu-acceleration.md`, the part a person sees. The first half (main finds the add-on, photo jobs use it, the probe reports it) is on `main`.

**Goal.** A person with an NVIDIA graphics card installs the GPU add-on from a file in Settings, Processing tools, sees whether their card is used, can test it, switch it off and remove it. A person without the add-on sees one extra, clearly optional card on that page and nothing else new anywhere.

**Where things stand.** The add-on is a file beside the installer and the pipeline pack (`pipeline-addon-cuda-<version>-win-x64.tar.gz`, 729 MB; 1,123 MB installed). Today it is used only when someone unpacks it by hand into `<data folder>/runtime/`. The app then passes it to photo jobs, and depth maps and fusion run on the card (pack 0.5.4). Nothing on screen mentions it.

## Decisions for the founder

Each has a recommendation; the build follows the recommendations unless told otherwise.

1. **Who is told that the add-on exists?** The GPU plan's note of 11 Oct says that on a computer with an NVIDIA card and no add-on, the wizard and Settings say that it exists and where to install it. The Orchestrator asked, for the team build, that without an add-on the pages read exactly as today apart from one optional row, and two tests pin the wizard's sentence ("Runs on the processor. Graphics card acceleration is not available yet.") and that Options never says "not installed". Options: (a) Settings only: the optional card on Processing tools is the one place; the wizard changes its line only once an add-on is installed. (b) Also the wizard, for NVIDIA owners: its line becomes "NVIDIA GeForce RTX 5070 Ti: the GPU add-on would speed this up. Install it in Settings, Processing tools." **Recommended: (a) now, (b) when the add-on has a download place**, because today a tester can only install a file someone handed them, and a sentence that sends people looking for a file they do not have is worse than silence.
2. **Where does the add-on sit on the page?** Options: a second card under "Install or update from file", titled "Graphics card (optional)"; or its own block under the page. **Recommended: a second card in the same block**, so the three files a tester gets (installer, tools, add-on) are handled in one place.
3. **What does the wizard say once an add-on is installed?** In Options, under "This computer and the cameras", in place of today's sentence: ready: "NVIDIA GeForce RTX 5070 Ti, 16.0 GB: used for depth maps and fusion."; switched off: "The graphics card is switched off in Settings. Runs on the processor."; not ready: the reason in words, for example "The GPU add-on needs graphics driver 528.33 or later (found 512.15). Runs on the processor." Never a promise of a time. **Recommended: as written.**
4. **The estimate.** The wizard's time estimate does not know the add-on (the probe's `cuda` stays false): with the card it will overestimate. Measured factors need the recorded bench of WP6 and a real flight. **Recommended: leave the estimate as it is in this package** and add one note under it when the card is ready: "With the graphics card, depth maps and fusion take less than this."
5. **Macs and computers without an NVIDIA card.** The add-on is for Windows x64 with an NVIDIA card. **Recommended: on other platforms the card is not shown at all; on Windows without an NVIDIA card it is shown, and an install is allowed** (the card's test then answers "No NVIDIA graphics card was found" in the row), since Chromium does not always list every card.

## What gets built

- **Install from file, with the pack's own checks.** `apps/desktop/src/main/jobs/packInstall.ts` unpacks and verifies an archive today for the pack only. Its unpack, verify, peek and find functions take a _kind_ (pack or add-on): the top folder's pattern, the archive name's prefix, the manifest's schema, and one fit test. For the add-on the fit test is its platform and its `packRange` against the pack in use, and there is no Python to look for. Every security check stays exactly as it is: path segments, one top folder, no links out, no devices, exclusive writes, the entry and size caps, every file's size and SHA-256, a temporary folder inside `runtime`, rename only after all checks. One install runs at a time across both kinds (they share the temporary folders and the lock).
- **Remove and test.** Remove moves the add-on's folder to the bin, refused in words while a photo job runs. Test runs the card's self-test now, bypassing the ten-minute memory.
- **The switch.** "Use the graphics card for photo processing", on by default, stored in its own file `processing.json` (`aio.processing-settings/1`, `gpu`: `auto` or `off`) in the user profile, because `settings.json` keeps its 0.9 keys. `QUADRION_PHOTO_GPU=0` still overrides it.
- **The probe does not wait.** Opening the wizard never waits for the card's self-test: the probe answers with what is known and the test runs behind it.
- **Diagnostics.** The bundle's `packs.json` gains the add-on's state.

- **Batch A:** T1 alone (everything builds against it).
- **Batch B (parallel, no shared files):** T2 (`packInstall.ts`, its fakes and tests), T3 (`processingSettings.ts`, its test) and T6 (`hardware.ts`, `ProcessWizard.tsx`, `estimate.test.ts`).

- **Critical path:** T1, T2, T4, T5, T7.

## Review focus

1. **A person without the add-on.** Processing tools reads as today apart from the one card; the wizard reads exactly as today. The existing end to end specs pass unchanged, which is the test.
2. **An add-on file in Downloads is never offered as processing tools**, and the other way round.
3. **An install of one kind while the other runs** answers "busy" and deletes nothing of the running one.
4. **Removing the add-on while a photo job uses it** is refused in words, not half done.
5. **A hostile archive** meets the same refusals as for the pack; no check is loosened to fit the add-on.

## How to test (once built)

1. Open Settings, Processing tools. Under "Install or update from file" there is a card "Graphics card (optional)" that says the add-on is not installed.
2. Click **Choose file** in that card and pick `pipeline-addon-cuda-0.1.0-win-x64.tar.gz`. A progress bar runs; then the card names the graphics card and its driver and says it is ready.
3. Click **Test**. The card says the graphics card passed.
4. Open a project with an aligned photo run, start Create maps from photos, open Options: under "This computer and the cameras" the line names the card and says it is used for depth maps and fusion. Start the run; the log says "Depth maps on NVIDIA ...".
5. Back in Settings, switch **Use the graphics card for photo processing** off; the wizard's line says it is switched off; a new run's log does not mention the card.
6. Click **Remove** in the card and confirm; the card says not installed again and the folder is in the Recycle Bin.

## Out of scope

Downloading the add-on from within the app; GPU pair matching (WP4); the estimate with measured factors and the recorded bench (WP6); macOS, AMD and Intel cards.
