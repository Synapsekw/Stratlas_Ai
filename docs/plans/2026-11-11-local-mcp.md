# Local MCP server (intelligence review Wave 3, X1)

Brief: roadmap `docs/plans/2026-10-30-intelligence-review.md` Wave 3 row X1, study
`docs/design/intelligence-review-2026-10/research.md` section 3, founder decision 5 (local only,
read-only first, the same tool registry as the agent). Built autonomously (founder go, 11 Nov
2026); every call below is decided here and recorded in the session note.

## Goal

Outside agents (Claude Code, Claude Desktop through a bridge, other MCP clients) can ask the open
project what the in-app agent can read: list issues, search the fact index (`query_facts`), read a
thing's history (`history_of`), volumes, surveys and so on. Nothing they call can change the
project, move the view or send imagery.

## Decisions

1. **Transport: Streamable HTTP bound to 127.0.0.1 only.** The packaged app has the Electron
   `runAsNode` fuse off (`electron-builder.yml`), so a stdio launcher that runs on the app's own
   Node cannot ship without weakening a security fuse, and a second Electron instance as a stdio
   bridge would fight the single-instance lock and start slowly. Claude Code and most MCP clients
   speak Streamable HTTP with headers; Claude Desktop reaches it through `mcp-remote` (needs Node on
   the computer). The listener is created with host `127.0.0.1` and never another interface; the
   SDK's DNS rebinding protection only allows `127.0.0.1:<port>` and `localhost:<port>` Host
   headers, and a request that carries a browser `Origin` is refused.
2. **Auth: a bearer token per server.** 32 random bytes (base64url), made when the server is
   first switched on, kept in `userData/mcp.json` (the person's own profile, which other Windows
   users cannot read), compared in constant time. "New token" makes another one and ends every
   session. A request without the right `Authorization: Bearer` header gets 401 before the MCP
   layer sees it. The port is kept with it so the pasted config keeps working across restarts; if
   the port is taken the server takes a free one and the snippet shows the new one.
3. **Off by default**; the switch is on Settings > AI providers ("Outside apps (MCP)"), with the
   address, the token (hidden until shown), copyable configs for Claude Code and Claude Desktop,
   the connected clients (name and version from the MCP `initialize`, since, calls) with
   Disconnect, and New token.
4. **Tools: the agent's read tools, from the same specs.** `packages/ai/src/mcp-tools.ts` keeps a
   classification of every read tool (`expose` or `exclude` with a reason); the MCP tool list is
   built from `allToolSpecs()` (name, description, JSON Schema of the zod input), so it never
   drifts. A parity test fails when a read tool exists that is not classified, or when anything
   that is not `risk: 'read'` is exposed. Excluded: `list_sites` (it spans every project of the
   library, whose privacy settings differ). Image results are dropped (read-only first, no
   imagery leaves through MCP).
5. **Execution: in the renderer, through the agent's own executors.** Main validates the input
   against the spec and sends `mcp:call`; the renderer runs `runRendererTool` with the agent's
   default tool context and answers `mcp:result`. Same code path as the in-app agent; a call times
   out after 30 s.
6. **Privacy: an MCP client is treated like a cloud provider.** A project is served when the
   cloud AI gate would allow a cloud provider (cloud AI on, offline-only off, the package or
   manifest policy allows), or when the person allows outside apps for that project ("Let outside
   apps read this project", kept per project in `userData/mcp.json`). A package or manifest that
   forbids cloud AI is never served, the per-project switch cannot override the builder's policy.
   Packages have no fact index anyway.
