# The agent can show you things: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Every task is TDD: write the failing test, see it fail, implement, see it pass, commit.

**Goal:** The agent that already ships keeps one conversation on every project screen, can open Media and Issues with a filter set, knows which findings sit on which asset, and shows a finding in one step, so "take me to the most severe point on this asset" and "open up images with the highest level of severity" work.

**Architecture:** No new engine. `@aio/ai` gains a pure asset index, five navigate tools and richer issue rows; the tools reach the app only through new optional `AppHooks`. The Media and Issues filters move from component state into two small zustand stores so a hook can set them. The desktop renderer owns one `AgentSession` for the app and mounts the same `AgentPanel` on Scene (where it is today) and in a folding column on Issues, Media, Detections and Reports.

**Tech stack:** TypeScript strict, React 19, zustand vanilla stores, zod tool inputs, Vitest, Playwright (Electron). No new dependency.

**Spec:** `docs/plans/2026-10-11-ai-agent-design.md` (read it before any task).

## Global Constraints

- TypeScript strict: no `any`, no non-null assertions (`!`), public API of a package from its `src/index.ts`.
- The renderer never imports `electron` or `node:*`.
- No change to `@aio/schema`, to IPC channels, to the main process, to providers, routes, the send preview, approvals or the cloud AI switches. If a task believes it needs one, it stops and reports.

- Keep edits to `packages/ai/src/tools.ts`, `apps/desktop/src/renderer/App.tsx`, `apps/desktop/src/renderer/workspace/WorkspaceScreen.tsx` and `packages/ui/src/i18n/en.ts` small and local (new lines grouped in one place): four other branches land first and touch them.

## Review Focus

Inputs the spec implies that are most likely to bite. Each has a test in the task named.

1. A request about an asset typed on Media, where the 3D scene is not mounted: the asset bounds come from the cache or the tool says the model is still loading; it never answers "no findings on this asset". (Task 2, Task 6)
2. Several findings share the worst level: the result names the others and the count, and the pick is the first by code, the same every time. (Task 6)
3. A finding marked only on a photo: the camera goes to the photo's pose and the result says `photoOnly: true`; a photo without a pose selects the finding and says there is nothing to fly to, without throwing. (Task 6)
4. The project changes while the column is open on Media: the conversation resets, both scope chips clear, and the asset cache of the old project is not used. (Task 3, Task 4, Task 7, Task 8)
5. The column open at 1100 x 700 on Media and Issues: the screen beside it stays usable, nothing scrolls sideways, and the title bar button stays reachable. (Task 7, Task 10)
6. A severity word that is not a level value: `show_photos` and `show_issues` accept only a level value, `uncertain` or `highest`; anything else is an input error the model can read and correct. (Task 6)

```ts
export interface AssetBox {
  tag: string;
  area?: string;
  box: PlaceBox;
}
export interface AssetLink {
  asset: string;
  area?: string;
  how: 'inside' | 'near';
  distanceM: number;
}
export interface AssetIndex {
  /** none: the project has no tagged assets. loading: it has, but their bounds are not known yet. */
  status: 'ready' | 'loading' | 'none';
  boxes: readonly AssetBox[];
  /** Issue id to its asset. An issue that is absent has no asset. */
  links: ReadonlyMap<string, AssetLink>;
  /** Ids of issues with no 3D point (marked on a photo or a map only). */
  unplaced: readonly string[];
}
export const ASSET_SLACK_M = 0.5;
export const ASSET_NEAR_M = 5;
/** Pure: the smallest box that contains p (with slack), else the nearest within nearM, else null. */
export function assetOfPoint(p: Vec3, boxes: readonly AssetBox[]): AssetLink | null;
/** The index of the open project. Bounds are measured in the scene when it is there and remembered per project. */
export function assetIndex(ctx: RendererToolContext): AssetIndex;
/** Forget remembered bounds (tests, and a project that changed its tags). */
export function clearAssetCache(): void;
/** "selection", a tag or an area name to the issue ids on it. Throws ToolError when loading or unknown. */
export function issuesOn(
  ctx: RendererToolContext,
  where: string,
): { label: string; ids: string[]; unplaced: number };
export interface IssueDetail {
  id: string;
  code: string;
  title: string;
  classId: string;
  severity: SeverityLevel;
  severityLabel: string;
  status: string;
  source: string;
  layers: string[];
  asset?: string;
  area?: string;
  position?: Vec3;
  photos: number;
  photoOnly: boolean;
}
export function describeIssue(
  ctx: RendererToolContext,
  issue: Issue,
  index: AssetIndex,
): IssueDetail;
export function severityLabel(ctx: RendererToolContext, issue: Issue): string;
```

Rules to implement:

- A point is inside a box when it is within `ASSET_SLACK_M` of it on every axis. Among containing boxes the one with the smallest volume wins; ties by tag order. Distance to a box is the Euclidean distance from the point to the box (0 inside).
- An issue's point is `boxCentre(boxOfPoints(issuePoints(issue)))`.
- `status`: `none` when no mesh layer has `tags`; `loading` when tags exist and no asset place has a `box` and nothing is remembered; otherwise `ready`.
- The cache is a module `Map<projectId, { tagCount: number; boxes: AssetBox[] }>`. It is written whenever a measure yields at least one box and read when the scene gives none. A different `tagCount` discards the entry.
- `issuesOn`: `"selection"` uses `ctx.workspace.getState().selection` (kind `asset`: its tag; otherwise `ToolError('Nothing is selected that findings can sit on. Name an asset or an area.')`). A name goes through `resolveName(ctx, where, ['asset', 'group'])`; a group matches links by `area`. `status === 'loading'` throws `ToolError('The 3D model is still loading, so findings cannot be matched to assets yet. Open Scene and try again in a moment.')`. `status === 'none'` throws `ToolError('This project has no tagged assets.')`.
- `describeIssue`: `position` is the issue point rounded to one decimal; `photos` the count of distinct photos of its image sightings; `photoOnly` true when it has image sightings and no 3D point; `severityLabel` from the issue's own severity model (`uncertain` uses the model's uncertain label, else `Uncertain`; an unknown value is `Level <n>`).
