# Insta360 native files: implementation plan

Design: `2026-10-11-insta360-native-design.md`. Branch `feat/insta360-native`.

Global constraints: no new lens model, no new layer kind, no new value in an existing enum; ffmpeg
stays an external program; no real footage, folder or site name in the repo; the manifest is not
written by a walk import; edits to files other branches also touch (`raw.ts`,
`builder/state.ts`, `ImportPanel.tsx`, `splitModel.ts`, `SplitPanes.tsx`, `en.ts`) stay small.

## Tasks

Each task is test first: the failing test, then the code.

### T1 Contract (`@aio/schema`, docs)

- `packages/schema/src/walks.ts`: `WALK_SCHEMA`, `WalkLayout`, `WalkFile`; export from `index.ts`.
- `versions.ts`: registry row `aio.walk` (`walks/<id>/walk.json`, since 0.11).
- `ipc.ts`: `builder:import` request gains optional `as360`; new channel `walks:list`.
- `docs/architecture/contract-changes.md` row; `data-conventions.md` section 32.
- Tests: `walks.test.ts` (a full file parses; a file without `stitch` parses; a newer version is
  refused by `readVersioned`; the registry row; both IPC shapes); `m11.test.ts` list of 0.11
  families gains `aio.walk`.

### T2 MP4 track reader (`@aio/video`)

- `mp4.ts`: `readMp4Tracks(read, size)` returns every track (`handler`, `width`, `height`,
  `codec`, `durationMs`, `fps`) and `spherical` (`equirectangular` when the Spherical Video
  metadata, version 1 or 2, says so). `readMp4VideoInfo` is unchanged. Exported from
  `telemetry-node.ts` and `index.ts`.
- Tests: `mp4.test.ts` builds a two-video-track `moov` in memory and reads both; a file with the
  spherical XML box reads as equirectangular; one without reads as none.

### T3 Recogniser (`@aio/project`, pure)

- `builder/walkSource.ts`: `insta360Name(name)` (role `clip` or `proxy`, stamp, sequence, local
  capture time), `proxyOf(name, others)`, `classifyWalkSource({ name, tracks, spherical,
trailer })` returning a layout or a refusal with its message, `isWalkExt(ext)`.
- Tests: `walkSource.test.ts`: X4 clip (two square tracks), `.lrv` (one 2:1 track), an `.insv`
  with one track (refused, message says one lens stream), unequal tracks (refused), a 2:1 MP4
  (equirect), a 16:9 MP4 (refused), a 16:9 MP4 with spherical metadata (equirect), name pairing
  of `VID_` and `LRV_` files, names without a stamp.

### T4 Stitch arguments and runner (`@aio/project`)

- `import/stitch.ts`: `walkSize(layout, w, h)`, `stitchArgs(o)`, `equirectCopyArgs(o)`,
  `hasV360(filtersText)`, `parseProgress(chunk)`, `ffmpegCheck(bin)`, `runFfmpeg(args, { onTime,
signal })`, `makeWalkCopy(...)`. `proxy.ts` exports `encoderArgs` (one word added).
- Tests: `stitch.test.ts`: the filter graph for two streams (fps halving, `hstack`, `v360` with
  size), for one frame (no `hstack`), audio mapped as optional and kept as AAC, keyframe and rate
  arguments, sizes (2880 square gives 3840 x 1920; 832 gives 1664 x 832; odd sizes come out
  even), the copy arguments never contain `v360`, `hasV360` on real `-filters` text with and
  without the filter, the progress parser on a chunk of `-progress` output.

### T5 Walk importer and list (`@aio/project`)

- `builder/walks.ts`: `WalkTools` (injected: `tracks`, `tail`, `check`, `stitch`, `copy`,
  `poster`), `importWalk(root, file, deps)`, `listWalks(root)`, `walkMissingMessage(check)`.
  Staging folder `walks/.<id>.part/`, renamed to `walks/<id>/` last.
- `builder/raw.ts`: `.insv` and `.lrv` branch; `deps.as360` sends `.mp4` and `.mov` the same way;
  proxies in the same import are skipped; the manifest is not rewritten for walk-only imports.
- `builder/index.ts` exports.
- Tests: `walks.test.ts` with fake tools: a clip becomes `walks/<id>/` with a valid `walk.json`;
  ffmpeg missing and `v360` missing give the two messages and leave no `walks/` folder; a failed
  stitch leaves nothing; an `.lrv` beside its clip in one import is skipped; an `.lrv` alone
  imports with the note; a second import of the same name gets a new id; `listWalks` skips broken
  files. `raw.test.ts`: `.insv` with no walk tools reports "not available"; a walk-only import
  writes no manifest backup; an MP4 with `as360` does not ask for an SRT. `plan.test.ts`:
  `walks/` files are package members.

### T6 Main (`apps/desktop/src/main`)

- `walks.ts`: `walkTools` (MP4 tracks through `@aio/video/telemetry`, the tail mark, ffmpeg check
  cached per run, stitch with progress), `listProjectWalks`, `packageWalks`.
- `builder.ts`: passes `walk`, `as360` and the stitch progress to `builder:progress`.
- `index.ts`: `walks:list`; `preload/index.ts`; `journal.ts` `READS`.
- Tests: `walks.test.ts` (list from a folder; list from a package archive; progress text),
  `journal.test.ts` (`walks:list` is a read).

### T7 Sphere view (`@aio/video`)

- `panoVideo.ts`: `createPanoSphere()`, `lookTarget(look)`, `createPanoVideoView(host, video)`
  (renderer, camera, dirty-flag render loop, resize observer, dispose).
- Tests: `panoVideo.test.ts`: the picture centre lies along local north, a quarter to the right
  lies east, the top is up; `lookTarget` follows `azElToDir`.

### T8 Pane, list and action (renderer, `@aio/ui` strings)

- `workspace/splitModel.ts`: `walk360` in `PaneKind`, `PANE_KINDS`, `paneOptions` (new optional
  argument). `SplitPanes.tsx`: `useSplit` passes the walk count (two lines).
- `walks/walkStore.ts`, `walks/walkModel.ts` (time text, key handling, pure), `walks/Walk360Pane.tsx`,
  `walks/WalkList.tsx`, `walks/walkMounts.tsx` (registers the pane; imported once from
  `m8Mounts.tsx`).
- `builder/state.ts`: `.insv` and `.lrv` in the filter, `pickAndImport360`, refresh of the walk
  list after an import. `ImportPanel.tsx` drop hint. `shell/Palette.tsx` command. `shell/Sidebar.tsx`
  one line for the list. `packages/ui/src/i18n/en.ts` strings.
- Tests: `splitModel.test.ts` (the pane is offered only with a walk; a remembered `walk360`
  falls back without one), `walkModel.test.ts`, `walkStore.test.ts`.

### T9 End to end

- New `apps/desktop/e2e/walk-360.spec.ts` (see the design, Testing).
- Existing specs rerun because their code changed: `builder.spec.ts`, `video-first.spec.ts`,

### T10 Docs

- `docs/guide/08-building-projects.md` section, `docs/TESTING.md` founder steps,

## Execution DAG

```
T1 ──┬──────────────► T5 ──► T6 ──┐
T2 ──┤ (T3 needs T2's track type)  ├──► T8 ──► T9 ──► T10
T3 ──┤                             │
T4 ──┘                      T7 ────┘
```

| Task | Depends on | Packages touched                           |
| ---- | ---------- | ------------------------------------------ |
| T1   | none       | `@aio/schema`, docs                        |
| T2   | none       | `@aio/video`                               |
| T3   | none       | `@aio/project` (own track type, no import) |
| T4   | none       | `@aio/project`                             |
| T5   | T1, T3, T4 | `@aio/project`                             |
| T6   | T2, T5     | desktop main, preload                      |
| T7   | none       | `@aio/video`                               |
| T8   | T1, T6, T7 | desktop renderer, `@aio/ui` (strings)      |
| T9   | T8         | desktop e2e                                |
| T10  | T9         | docs                                       |

Parallel batches (no shared files inside a batch):

1. T1, T2, T3, T4, T7 (T2 and T7 are both in `@aio/video` but in different files; `index.ts`
   exports are added by T7 last).
2. T5.
3. T6.
4. T8.
5. T9, then T10.

Critical path: T3/T4 to T5 to T6 to T8 to T9. T7 is the only task off it; the player is the least
certain part, so if T7 or the pane in T8 is not solid, the branch stops at T6 plus the list (a
working import with a written plan), and the pane is left out whole.

This plan is built by one session in batch order, because the workstation is shared and heavy
commands run one at a time; the batches say what could run side by side.
