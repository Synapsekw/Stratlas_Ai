# ODM replaces our photogrammetry engine

## What changed

- OpenDroneMap 3.6.2 (pinned, SHA-256 checked, downloaded from its GitHub at run time, AGPL-3.0, about 1.0 GB, per-user, no admin prompt) now runs alignment, ground control and products as a separate program; outputs come in as the same layer kinds. Quick makes no 3D model.
- Settings > Processing tools has a "Processing engine" card (explanation, Download and install with progress, version and folder, "Use the graphics card" switch, Update, Remove, a warning before replacing another ODM install). Create maps shows "Install the processing engine first" when ODM is missing.
- Our own dense, fuse, DSM, DTM, ortho, mesh and texture engine, COLMAP alignment and the GPU add-on are deleted. Pipeline pack 0.8.0; photogrammetry is Windows x64 only. Jobs begun by the earlier engine are refused with one plain sentence.
- Real-ODM findings: its placeholder nvcuda.dll made OpenMVS run dense on the CPU, so our own install renames it (founder approved; dense step on 24 photos 41 s GPU vs 136 s CPU on an RTX 5070 Ti). Ground classification breaks on paths with spaces, so unsafe folders go through a junction. Ground control needs opensfm/image_list.txt invalidated or GCPs are ignored (verified, 9 mm average error on the sample). Threads = clamp(min(CPUs-2, RAM GB/3), 2, 32). The stall watchdog counts ODM's CPU time; ODM children run in a Windows job object so quitting the app ends them.
- Tests: 1,184+ Python tests, `pnpm check` green (about 7,976 vitest); e2e processing-tools, photo-process, photo-products, photo-change, gcp-marking, agent-photo, processing-drawer and walk-360 run the CI way; opt-in `test_odm_real.py` (24 photos: align Fast about 1 min, products Fast about 1.5 min, Standard about 6.5 min).

## Why

A real 995-photo run on pack 0.7.0 spent 7.5 h stuck in our own orthomosaic (one core, cache thrash, about 830 windows, days to finish). Founder, 14 Oct: stop rebuilding what proper engines do; switch to OpenDroneMap.

## How to test

1. Settings, Processing tools: the Processing engine card at the top explains ODM.
2. Click Download and install: progress through downloading, checking, installing, checking the installation; then Installed, ODM 3.6.2 and its folder, and "Graphics card: NVIDIA GeForce RTX 5070 Ti, used for processing".
3. Open a project with drone photos, Create maps from photos, Standard, start: the Processing drawer shows ODM's stages; ortho, DSM, DTM and point cloud layers appear.
4. Open the job log: thread count and "Graphics card used for features: yes; for dense matching: yes".
5. Cancel during dense matching, then Resume: it continues from the stage after the last finished one.
6. Switch "Use the graphics card" off and run again: the log says the card was not used.
7. Remove the engine: the card says Not installed and Create maps shows "Install the processing engine first".
