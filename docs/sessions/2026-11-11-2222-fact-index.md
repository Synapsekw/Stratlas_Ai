# Project fact index, its agent tools and project search

## What changed

- This PR adds the project fact index (intelligence review Wave 3, M1; study `insight.md` 5.6 and 5.7) in a new package, `@aio/facts`, which depends on schema and journal only.
  - It reads a project folder tolerantly.
  - It extracts typed facts: survey dates, layers, photos, measurements, volumes per date, detections and their reviews, issues, survey QA, photo accuracy, change sets and items, thermal hot spots and candidates, walks, and journal ops.
  - It extracts cross-kind links: on-photo, on-survey, in-layer, issue, in-set, about, qa, and inside (a point record inside a polygon measurement on the same date, for example an issue on a pile).
  - It keeps both in SQLite with FTS5 through `node:sqlite`, which is built into Electron 44 and Node 24, so nothing native ships.
  - The query API (`query`, `historyOf`, `linksOf`, `status`, `dump`) is documented in `packages/facts/README.md` for A3 and X1.
- The index is derived, never a source of truth.
  - Main keeps one file per folder project in `userData/fact-index/`, never in the project folder.
  - Deleting it and building again gives the same rows (tested).
  - An update applies only the rows that differ from a fresh extract, so an updated index equals a rebuilt one (tested).
- Main lifecycle (`apps/desktop/src/main/facts.ts`):
  - The index is built in the background about 2 s after a folder project opens, one project at a time.
  - It is updated about 1.5 s after each `journal:changed`.
  - `facts:rebuild` deletes the index and builds it again.
  - A damaged or older-version file is dropped and rebuilt.
  - A project's index is removed when the project is deleted.
  - Packages have no index.
- Agent tools `query_facts` and `history_of` (read-only, `packages/ai`):
  - They are offered only while the index is ready (`AgentFacts.factIndex`).
  - `history_of` takes a subject id or a name. A name that matches several things is refused, and the refusal lists the candidates.
  - They are not in the compact profile, which is full at 34 tools.
  - Scripted rules and four E1 eval cases were added: two on the change demo and two on the quarry.
- Project tab: a new "Search this project" section (`project.search`, after "In this project", closed by default).
  - A search field, results with their kind, date and figure, and the history inline on a click.
  - A state line while indexing, a count line, and a "Rebuild index" button.
- Contract change: "Fact index schema (derived, not a source of truth)" (`@aio/schema` `facts.ts`, IPC `facts:*`, event `facts:changed`, `AgentFacts.factIndex`).
- No pipeline change, so no pack bump.

## Decisions made on the founder's behalf

- `node:sqlite` rather than a native binding. The repo shipped none.
- The index lives in userData, so it is never synced, packed or journaled.
- An incremental update is a whole-project extract, diffed row by row. Links across files make a per-file update wrong, and extraction is cheap next to a pipeline job.
- Subjects use the journal's record kinds, so a journal op maps to the subject it changed.
- An update after the first build keeps the state `ready`, so the agent tools do not flicker away while the index catches up.
- Search lives in the Project tab, not the palette (shell).

## How to test

1. Open the change demo (Demo change site). Open the Project tab's "Search this project" section. Within a few seconds, a count line says how many records are indexed. (`e2e/facts-search.spec.ts`)
2. Type "corrosion". The issue "Corrosion on the T-201 shell" is listed. Click it: its history opens inline, with its survey date among the linked records. Click again (or press Enter): it closes. (`e2e/facts-search.spec.ts`)
3. Add a measurement named "North stockpile" and type "stockpile": it is listed as a measurement. (The spec writes it into the working copy and reloads: `e2e/facts-search.spec.ts`.)
4. Press "Rebuild index". It indexes again and shows the same results. (`e2e/facts-search.spec.ts`)
5. With an agent provider set, ask "What happened to Stockpile SP1 over time?" on the quarry demo. The agent calls `history_of`. These are E1 cases in `agent-eval.suites.ts`, which are not run in CI. The tool, its routing and the offer rule are covered by `packages/ai/src/fact-tools.test.ts` and `tools.test.ts`.

## Open threads

- A sync runs on main's thread (`node:sqlite` is synchronous). The demo builds in milliseconds. A very large project (tens of thousands of detections) may pause main briefly on each update; a worker thread is the next step if that shows.
- Status words (accepted, draft, hold) show raw in the search results.
- Photos without a position, panoramas and RF or antenna records are not indexed yet. Antennas arrive with M2 tracks.
- Local semantic search (study 5.7, embeddings over the same facts) is not part of this PR; FTS5 is the first step it named.
- The `inside` link uses a measurement's outline per date, or its points for a site-wide one. Issues on mesh sightings are placed only for a surface point.
