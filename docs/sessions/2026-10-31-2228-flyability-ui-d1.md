# Flyability import UI, batch D1

## What changed

- An addendum plan splits the UI half of phase 1 into work that does not need UI Wave 2 (this PR) and three small hook-ups that wait for W7, W8 and W11.
- Spaces: an active space per project, the stage and the Issues list follow it, and layers of other spaces stay hidden as an invariant (after a switch, an import finishing or a date jump). Hidden layers stay hidden on the first entry into a space.
- Flight lines drawn in 3D from the import's pose files, with their own Layers group and fly-to.
- The Inspector picker on the `@aio/ui` Dialog, opened from Add data and after a library drop; a re-drop reopens the same project (a hashed, never-packed `flyability-source.json`); a cancelled import opens nothing.
- Move point on the shared right-click registry (`finding.movePoint`), the issue-row menu hosted app-wide, undo through the toast host, and a plain-language location-check row in the finding card; agent actions exclude the view-click actions.
- Pre-flip fixes (no half-made project folder, OS files skipped, local-project message, altitude plan for local projects, IPC parse tests). Everything stays off for users in this PR.

## Why

The rest of phase 1 waits on UI Wave 2; landing this now keeps conflicts in hot shared files (Stage, actions) small.

## How to test

No user-facing behaviour to test; covered by the test suite (the import stays off until the flag flips).
