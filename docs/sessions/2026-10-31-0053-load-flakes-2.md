# Three more desktop tests hold up under load, and cover pictures retry on Windows

## What changed

- `95ec23c3f`: `setCover` (`apps/desktop/src/main/covers.ts`) writes `thumbnail.jpg` through a temporary file and puts the kept original back. Both renames now go through `renameWhenFree` from `@aio/project/fs`, which tries again while Windows refuses a rename because a scanner is reading the picture just written. A new test in `covers.test.ts` refuses each rename once, and its cleanup retries.
- `7f2fb4918`: `PlaceModel.test.tsx` imported `ImportPanel` inside its last test, so transforming that module graph (about 1.6 s alone) counted against the test's 5 s and ran over it under load. It now loads with the file's other modules, and the test itself takes milliseconds. `frames.test.ts` starts real ffmpeg processes: it encodes the test video in `beforeAll`, and one test runs four decodes, one of them blocking. They take many seconds on a loaded computer, so the file allows 60 s per test and hook, and its cleanup retries.

## Why

All three timed out in loaded `pnpm check` runs and passed alone (merge coordinator request, 31 Oct).

## Evidence

Each phase ran the three files 4 at a time next to 4 `@aio/project` runs (`--retry=0`), in two rounds, under the shared heavy-run lock.

- Before: 5 of 8 runs failed. Every failure was the `frames.test.ts` test "gives the same pixels as ffmpeg with its default threads", which timed out at 5 s. `covers.test.ts` and `PlaceModel.test.tsx` passed in that load, but `PlaceModel`'s last test took 1.6 s even alone.
- After: 0 of 8 runs failed, with 45 of 45 passing in each.
- The new covers test fails against the old `covers.ts`.
- `pnpm check`: lint, format and typecheck green, and all three target files passed. 6 of 16,789 tests failed: 5 s timeouts in other files that pass alone, listed in the North Star (`collab.test.ts:285`, `packages.test.ts:80`, `panos.test.ts:331`, `update/websiteStorage.test.ts:111` (two cases), `renderer/survey/compareStore.test.ts:388`). The PC was running other sessions' checks and e2e at the same time.

## How to test

Nothing user-facing changes, apart from fewer "operation not permitted" failures when a project's card picture is changed or reset on a busy Windows machine. The test suite covers it.

- Other desktop tests still time out at 5 s in a loaded check (above). They need the same treatment, one file at a time.
