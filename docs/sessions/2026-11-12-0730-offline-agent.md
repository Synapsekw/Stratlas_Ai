# Offline AI on the bundled model, batch approvals, project notes, view-capture consent (A3)

## What changed

- This PR lets the Analytics pack's own model (Qwen3.5 9B on the pack's `llama-server`) run the in-app agent offline, in the compact profile, once it passes a tool-calling check on this computer.
  - `packages/ai/src/toolCheck.ts` is the check. It sends 12 requests in the 3D window with the compact prompt, the compact tool list and a window context like the app's: navigation, layers, issues, survey dates, a volume, a draft issue, and one "thanks" that must not call a tool. Each case is graded on the first tool call, its arguments and the case's argument check. 10 of 12 must pass. When two requests in a row fail to reach the server, the check stops and records nothing.
  - Settings > AI providers > Local model > Model to use offers "The bundled Analytics model". It has "Check tool calling" and the result line. The "Use Offline AI for everything" switch turns on only after a pass for the installed model's SHA-256 and llama.cpp release, so an update to either asks for a new check.
  - The runtime takes the model for each run through the photo ask's queue, lease and keep-warm (`localAsk.acquire`). While an approval card waits, the model is given back, so a queued detector run can start. When the person answers, the run takes the model again; if it is busy, the reply says "Offline AI is waiting for the model." A busy card refuses a new message with a plain message. Runs of a window that closes, reloads or crashes are cancelled, so the lease is released.
  - Other gate rules:
    - The engineer step, detection and telecom labelling never use the bundled route.
    - The renderer cannot write the stored check (`settings:set` drops it).
    - A pack whose `model.sha256` differs from its file list's entry is unusable.
  - The server's context is now 16 384 tokens for every launch. Taking the model for Offline AI needs 7650 MB free; detector runs and photo asks keep 7400 MB.
- Batch approvals: two or more write calls waiting in one turn show one card, "N actions waiting for you", with one ticked item per call, "Approve N" and "Reject all". Ticked items run one after another in the model's order. A failure stops the rest, which stay waiting. A second click is ignored while a batch runs. Every step keeps its own Undo. The full prompt asks the model to call related changes together.
- Project notes:
  - The notes live in `<project>/ai/memory.json`, at most 30 notes of 300 characters, and are read-only in a package or in a file the app cannot read.
  - The agent saves a note with `remember_note` and deletes one with `forget_note`. Both go through the approval card, and both can be undone.
  - Every message carries the notes in its window context as `projectNotes`. The prompt frames them as the person's saved preferences and project facts: data that never overrides the rules, an approval or a consent. A cloud send preview shows them.
  - Packages leave `ai/memory.json` out, and a package's notes are never sent.
  - The agent dock's new "This project" panel (the note button beside the message field) lists the notes. Each can be deleted, and the person can add one, one change at a time.
  - The fact index has a new kind `note` with an `about` link, so `query_facts`, `history_of` and the Project tab search find notes.
  - Over the local MCP server (X1), notes stay in the app: an outside app's fact queries leave them out.
- View capture asks once per project and per route class. The first `capture_frame` card offers "Allow for this project", "Just this once" and "Reject". Once allowed, later captures in that project on the same kind of route run without a card, and the step says so. Consent given on this computer (a local or bundled model) never covers cloud AI. "This project" has two switches, "On this computer" and "With cloud AI". The consent is tied to the project it was given in.
- Three reviews ran: two independent ones on the build and its fixes, then the coordinator's. Every finding of medium severity or higher is fixed with a test:
  - The engineer step can no longer use the bundled model's placeholder address.
  - A closed window cancels its runs.
  - The renderer cannot write the stored check, and the Settings check no longer overwrites a later change.
  - A second batch click is ignored.
  - Consent and notes are tied to their project, so a failed read never carries one project's notes into another's message.
  - An unreadable or newer `memory.json` turns read-only instead of being overwritten.
  - A server that dies during the check gives no verdict.
  - Coordinator's round: the model is given back while an approval waits; the extra memory need is the agent's only; consent is split by route; notes are framed as data and stay out of packages; the forget card names the note; an in-flight guard on Add and Delete; the new strings avoid the retired word.
- E1 has new cases for several drafts asked at once, one look at the view, remembering a stated fact, and not saving text that came from tool results.

### The real check on this computer

- Setup: Analytics pack 0.2.0, `qwen3.5-9b-q4_k_m`, llama.cpp b11489 started with the app's own arguments, RTX 5070 Ti.
- At the old `--ctx-size 8192` the request does not fit, because the compact profile is 10 957 prompt tokens. Without the project filter, the modelling correction tool's schema alone brings it to 68 674 tokens.
- At 16 384, three runs scored 11/12, 12/12 and 12/12, with no invalid call and a mean of 360 to 420 ms per case. The one miss answered the survey dates from the context in text instead of calling `list_surveys`.
- The server's graphics memory was about 6.6 GB at 8192 and about 6.9 GB at 16 384.
- `--jinja` is on by default in this build, so no new argument was needed.

### Evidence

- `pnpm check`: the only failures were the two settings key-set compat tests (`tools/compat/m10-additive`, `m11-additive`). Both are fixed in this PR and pass, 60/60.
- E2e run the CI way: 1100 x 720 at scale 1, WARP, `--workers=1`, every demo built.
  - Run one: 27 of 28 passed across `agent-offline-bundled`, `agent-batch`, `agent-view-consent`, `agent-memory`, `agent-local`, `agent-show`, `agent-pane`, `agent-photo`, `agent-camera`, `facts-agent`, `facts-search` and `mcp-server`.
  - The one failure was `agent-pane`: the notes button in the header left the bound view's chip too little room. The button now sits beside the message field.
  - Run two: `agent-pane`, `agent-memory`, `agent-view-consent`, `agent-batch`, `agent` and `agent-show` passed, 20/20.

## Decisions (on the founder's behalf)

- One server context, 16 384, for detector runs too: one server shape, about 250 MB more graphics memory.
- The bundled model is held for a run's model steps only and is given back while an approval card waits (coordinator's call).
- A batch is every waiting write of one turn. `capture_frame` keeps its own card.
- Notes go with the project, in its folder. Each one is shown on a card before it is saved, because a note steers later answers.
- View-capture consent is per project on this computer and per route class: local or bundled, and cloud (coordinator's call). A consent stored before this split counts for this computer only. An unknown route counts as cloud. "New conversation" in the same project keeps it.
- Outside apps over MCP never see notes (coordinator's call, 12 Nov).
- The UI says "Offline AI", because the glossary retires the word "agent" in strings.
- No pipeline Python and no Analytics pack change, so pack numbers stay at pipeline 0.35.0 and Analytics 0.2.0.

## How to test

1. Install the Analytics pack, then open Settings > AI providers > Local model and set "Model to use" to "The bundled Analytics model". It shows the model and pack version and says to check tool calling first. "Use Offline AI for everything" is disabled. [`agent-offline-bundled.spec.ts`]
2. Click "Check tool calling" (about a minute on the real model). It shows "Passed: N of 12 right ..." and the switch becomes enabled. Turn it on. [`agent-offline-bundled.spec.ts`; real run above]
3. Open the change demo and ask "Fly to tank T-201". The agent runs `find_places`, then `fly_to`, on the bundled model. [`agent-offline-bundled.spec.ts`]
4. With a model that answers in text only, the check says it made the right call in 1 of 12 (10 needed) and points to your own server or cloud AI. The switch stays disabled. [`agent-offline-bundled.spec.ts`]
5. Ask for three draft issues at once. One card lists three ticked items. Untick the second, then click "Approve 2": two steps are done and one is rejected. Undo on the first removes that draft only. [`agent-batch.spec.ts`]
6. Turn on "On this computer" under "Look at the view without asking" in "This project", then ask the agent on cloud AI to look at the view: the card still asks. Click "Allow for this project". Ask again: the capture runs with no card and the step says so. Turn off "With cloud AI", ask again, and the card is back. [`agent-view-consent.spec.ts`]
7. Say "Remember that the piles here are named SP-1 to SP-9". The card reads "Remember: The piles here are named SP-1 to SP-9". Approve it, and "This project" lists the note as saved by Ask AI. The next message's context carries it, and the send preview shows it. Undo on the step removes it. [`agent-memory.spec.ts`]
8. In "This project", add "Volumes go in the weekly report". It shows as added by you, and the fact index finds it. Delete it with its x. [`agent-memory.spec.ts`]
