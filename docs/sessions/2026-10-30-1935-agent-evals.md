# Agent eval regression suite (E1)

## What changed

- This PR grows the hand-run real-model check (`apps/desktop/e2e/agent-eval.spec.ts`) into a regression suite the agent items (A1, A2, A3) are measured against before and after.
- Suites: `tank-farm` (the founder's 22 plain requests, 90 percent bar kept), `tank-farm-more` (follow-ups in one conversation such as "Take me to the second one" and "Do the same for the bund", and wrong premises: "Delete all issues" must refuse or ask and leave every issue, unknown tanks and surveys must be said not to exist), `change` (survey dates, what changed, the new and resolved issue, the stockpile fill) and `quarry` (stockpile volumes and tonnes over three surveys; needs the pipeline Python). The new suites report without a bar until a baseline run exists.
- Known gaps sit on the turn that needs them: follow-ups that need tool results in history carry `gap: 'A1'`, questions that need survey and volume read tools `gap: 'A2'`. A failure on a turn that is no gap is a failure; a failing gap turn is listed as a known gap and left out of the pass rate; a case whose gap turns pass every attempt is listed as closed.
- Profiles: `anthropic` (model from `QUADRION_EVAL_MODEL`, default `claude-haiku-5-5`), `local` (an OpenAI-compatible server on this machine, `QUADRION_EVAL_LOCAL_URL` and `QUADRION_EVAL_LOCAL_MODEL`) and `scripted` (the stand-in model; proves the harness at no cost). The profile must be set explicitly: a key in the shell starts nothing, and `pnpm eval:agent` (tools/agent/agent-eval-run.mjs) refuses without one. The chat route is set through Settings, so no product code changed. CI still skips the whole file.
- pass^k: `QUADRION_EVAL_K` repeats each case; the table gives pass@1, pass^k, judged of k (PARTIAL when the provider refused some) and whether the tool sequence varied.
- Traces: each run writes one JSON file per suite into `.agent-eval/<run>/` (git-ignored): per case and attempt the verdict, the reason, and per turn the request, every tool step with its input and status, and the reply. `pnpm eval:agent:compare` diffs the two newest runs (fixed, broke, unknown when one side has no verdict, new, removed, tool sequence changed; pass@1 and pass^k before and after), and refuses runs of another profile, model or k unless `--force`.
- Grading stays code-based: app state, tool names and inputs, and plain checks on the reply (a figure within a tolerance and the direction of a change, a refusal or an explicit request to confirm, a "not found" tied to the thing asked about with no navigation, the dates named, "which ones" answers that name no code that does not qualify). Unit tests in `tools/agent/agent-eval.test.mjs`.

## Why

The intelligence review (agent.md section 3 and item 4.7) found the eval single-turn, tank-farm-only and Anthropic-only, with no record to compare runs by. The agent brain (A1) and the new read tools (A2) need a before and after.

## How to test

1. Build the app and demos: `pnpm build`, `pnpm demo:build --quick`, `pnpm demo:change --quick`.
2. Run the harness with the stand-in model, no key: PowerShell `$env:QUADRION_EVAL_PROFILE = 'scripted'; $env:QUADRION_EVAL_K = '2'; pnpm eval:agent`. Each suite prints its table (most cases fail: the stand-in is not a model) and the path of its trace.
3. Run it again, then `pnpm eval:agent:compare`: it lists the two runs and what changed between them.
4. With a key (see the spec header for keeping it out of the shell history): `$env:QUADRION_EVAL_ANTHROPIC_KEY = Get-Clipboard; $env:QUADRION_EVAL_PROFILE = 'anthropic'; pnpm eval:agent`. Without the profile it refuses to start. Haiku 5.5 is the default; `$env:QUADRION_EVAL_MODEL = 'claude-sonnet-5-5'` for the app's default chat model.
5. With a local server (Ollama): `$env:QUADRION_EVAL_PROFILE = 'local'; $env:QUADRION_EVAL_LOCAL_URL = 'http://localhost:11434/v1'; $env:QUADRION_EVAL_LOCAL_MODEL = '<a tool-calling model>'; $env:QUADRION_EVAL_LOCAL_KIND = 'ollama'; pnpm eval:agent`.
