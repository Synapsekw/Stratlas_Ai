# Model add-ons: download on demand, three add-ons wired in

## What changed

This PR builds Wave 3 item N1 of `plans/2026-10-30-intelligence-review.md` (plan `plans/2026-11-11-model-addons.md`, founder decision 4). The Analytics pack is not touched.

- **Add-on mechanism.** New contracts `aio.addon/1` (the manifest inside a gzipped-tar `<id>-<version>.aioaddon`), `aio.addon-catalogue/1` (`catalogue.json` at the add-on address, with each archive's URL, size and SHA-256) and `aio.point-classifier/1` (`packages/schema/src/addons.ts`).
  - Main (`apps/desktop/src/main/addons/`) reads the catalogue, downloads with resume (`downloadVerified`), checks the archive's size and SHA-256, unpacks into a staging folder, refuses links, absolute paths, `..`, unlisted entries and any file whose size or SHA-256 differs from `addon.json`, checks the files each kind needs, then swaps `<dataRoot>/runtime/addons/<id>/` in atomically.
  - IPC `addons:list`, `install`, `choose`, `installFile`, `cancel`, `remove` and the `addons:progress` event. Choose file installs only paths main's own dialog returned. Offline only blocks the catalogue and downloads, never Choose file.
  - Address: `QUADRION_ADDONS_URL`, then Settings `addons.baseUrl`; the built-in address is empty because nothing is published yet. https only, or http to loopback.
  - `tools/addons/build-addon.mjs` packs a folder into an add-on and merges its catalogue entry, for when the founder publishes them.
- **Settings, Models and detection, Add-ons**: one row per add-on with name, what it does, version, licence and the download size first; Download or Update in one click, progress with Cancel, Remove with a confirm, one Choose file for the section. Detection models marks an add-on's model **Add-on** and leaves its removal to the Add-ons row.
- **Road defects** (kind `detector`): its `model.onnx` and card are listed with the detection models (`where: 'addon'`) and run in the existing local ONNX detection.
- **Segmentation** (kind `segmenter`): a SAM-class ONNX encoder and decoder that Suggest boundaries and the review's outline assist use in place of the processing tools' model. It also turns on **Classify on point cloud** (photo right-click, `photos.classifyOnCloud`): new job `segment.lift` (pipeline pack 0.35.0) puts each outline through its posed photo onto a COPC cloud, keeps the points the photo saw (a depth buffer) and answers a lasso region in that camera's clip space with a depth band. The app adds the regions to the layer's cleanup recipe with the class picked, as one undoable step. `CleanupRegion` gains `depth` and `label`; both evaluators (viewer and pipeline) apply the band, pinned by the shared vectors.
- **Ground classifier** (kind `point-classifier`): **Also mark ground** in Clean up, Remove noise. Main swaps the window's `GROUND_REQUEST` for the add-on's `classifier.json` settings; the noise run runs PDAL SMRF as its own pass and merges only its ground points back as class 2, so noise and every other class stay as they were. The record carries `groundMarked`.
- **Bench.** `tools/detectors/bench.py --drafts <aio.detections file>` scores a finished run of any detector (the Road defects model run in the app) with the same truth, IoU matching, PR curve and references as a VLM run.
- **Pack.** Pipeline pack 0.35.0, the batch's shared bump (already on local `main`); this PR adds its lines to the 0.35.0 note and the Settings guide entry. `POINTCLOUD_GROUND_MIN_PACK` and `SEGMENT_LIFT_MIN_PACK` are 0.35.0 and both features are on the Processing tools list.
- **Contracts.** Rows in `architecture/contract-changes.md` for the add-on pack manifest and `pointcloud:readCleanup` `liftRun`.

## Decisions made on the founder's behalf

- The catalogue lives at the add-on address and is read on each list; the archive's hash comes from it, each file's from `addon.json`.
- Add-ons live under the data root's `runtime/` beside the packs.
- SAM 3 ships as an ONNX export run by the app's onnxruntime, with the interface MobileSAM uses, so no PyTorch runtime ships. The segmenter add-on takes the relaxed licence gate (warning shown), since its licence is shown before download and SAM 3's own licence was approved for internal use; the processing tools' model keeps the strict gate.
- Lifting answers recipe regions, so the recipe stays the one source of truth and Save and Export need no new path. One depth band per outline: a few ground points right at the foot of a wall behind the object can be taken (at most 0.5 % of a box test's points); points hidden under the object and ground beside it are not. Each photo is a pinhole camera with no lens distortion, and a photo stored rotated (EXIF orientation) is skipped as "not the shape of its photo".
- Ground is SMRF inside the noise run, not a new job, so the working copy, recipe and save flow carry it unchanged.
- The action sits on the photo menu because the action registry has no detection target.

## What was verified with real weights, and what was not

- **Segmentation, real weights (MobileSAM from processing tools 0.33.0).** Built into an add-on with `build-addon.mjs` (36.6 MB archive), installed through the main installer, found by `findSegmentModel` from the add-on folder, and one CPU segmentation of a synthetic disc gave a 32-vertex outline at 98.7 % of the disc's area (1.0 s first click, 0.25 s the second). A copy with one flipped byte in `encoder.onnx` was refused ("encoder.onnx in the add-on does not match its addon.json (SHA-256)...") and nothing was installed. A SAM 3 ONNX export was not run: exporting it needs PyTorch, which this PC does not have.
- **Road defects: not verified with real weights.** No road YOLO has been trained; the training needs PyTorch and the reviewed road defects. The integration is verified with the synthetic marker detector. `bench.py --drafts` is ready to judge it once a model exists; no bench numbers were produced.
- **Ground classifier, real PDAL (2.10.2).** SMRF through the noise run on synthetic clouds: open ground becomes class 2, a class-6 block stays 6, noise stays 7.
- **Lift**: synthetic cloud and posed camera through the real job and `evaluate.py`: over 90 % of the block's seen top and side taken, nothing under it, no ground beside it.

## How to test

1. Settings, Models and detection, Add-ons shows Road defects, Segmentation and Ground classifier, each with its licence and "Download (size)" (needs an add-on address; `e2e/addons.spec.ts` "downloads Road defects from the catalogue, lists its model and removes it").
2. Download Road defects: its row shows progress, then "Version 1.0.0"; Detection models lists the model marked Add-on, with no Remove there (same case).
3. Remove on the Road defects row, confirm: the row says Not installed and the model leaves Detection models (same case).
4. An add-on file that does not match its check is refused on its row and nothing is installed (`e2e/addons.spec.ts` "refuses an archive whose file does not match its manifest, and installs nothing"; with real weights, the tampered MobileSAM run above).
5. Turn on Offline only: Add-ons shows no Download. Choose file with a Ground classifier `.aioaddon` installs it, and nothing goes on the network (`e2e/addons.spec.ts` "offline only: no catalogue read, Choose file installs the Ground classifier").
6. With the Ground classifier installed, open a project with a point cloud, Clean up, Remove noise: "Also mark ground" is there, off. Tick it and run with processing tools 0.35.0: the result line adds "N ground points", the same count as the run record's `groundMarked` (`e2e/addons-pointcloud.spec.ts` "ground › Remove noise with Also mark ground marks ground points", real pipeline and real PDAL).
7. With the Segmentation add-on installed, on a posed photo with an outlined finding, right-click the photo in Inspect, Classify on point cloud, pick a class, Classify: "1 region", the region appears as one step in Clean up with a depth band and the photo in its label, and Undo takes it out (`e2e/addons-pointcloud.spec.ts` "lift › Classify on point cloud lifts a photo outline into one cleanup step", real pipeline, synthetic segmenter).
